# Carmanline 0.3.1

安卓公式与错题巩固应用。[下载 v0.3.1 安卓安装包](https://github.com/Yunoseek/carmanline/releases/tag/v0.3.1)。本地构建的安装包位于 `dist/carmanline-v0.3.1.apk`。

## 更新安装

直接在手机上打开新 APK，覆盖安装已有应用。包名与签名沿用 0.1.0，因此原来录入的公式、错题、接口设置和密钥可保留。不要先卸载旧应用，以免系统删除本机数据。

本次升级按旧示例的固定 ID 清理默认的 30 个公式、5 道错题及 1 个重点示例。用户录入的内容保留，即使它和某个示例的公式相同。新安装从空题库开始，不再提供内置样例入口。

## 本版变化

- JSON 输入栏新增“清空”，图片选择区新增“清除图片”；在当前页即可重新输入或选择同一文件。清除同时重置错误和对应未入库草稿，迟到的读文件/识别结果不会恢复已清空内容，不影响题库。
- 照片及 JSON 按条目校验：坏项单独列出原因，有效项继续录入；混淆项中存在坏项但仍有至少 3 个有效项时，保留该公式。多张照片中一张失败也继续处理其他照片。
- 取消原图、截图切块和逐张截图核对展示。结果页只展示文字与公式，照片也支持整批入库，用户自行检查内容；原图仅在主动调用 AI 修改时作为上下文使用。
- 外部提示词改为输出一个可复制的 JSON 代码块，公式和错题均提供含反斜杠命令的完整示例。App 内拍照提示词限制最多 12 条、每条 3 个混淆项，不再请求 bbox；不把任意积分常数的正负号变化作为错误选项。
- 对明确中断的模型返回，仅恢复已完整返回的条目并提示可能遗漏；空回复及格式错误显示简短原因，不再将整段原始 JSON 填入错误框。不会自动重试或猜补残缺公式。
- 拍照识别后的“对话修改”可向 AI 下达指令，连续修改当前草稿；“手动编辑”可修改科目、名称、内容、条件、选项和正确答案。草稿需明确确认后才入库。
- “录入 → JSON 导入”提供公式、错题各自的严格识别提示词，一键复制给其他 AI；返回结果可粘贴或选择 JSON/TXT 文件。此流程无需配置 App 内的 AI 接口。
- JSON 导入检查类型、必填字段、答案下标、混淆项、数学渲染和大小限制，错误定位到具体条目及字段；可逐条核对或确认整批入库，相同内容自动跳过。保存失败不推进草稿，也不留下半批数据。
- 拍照和对话共用已配置的模型服务；JSON 草稿的对话修改发送纯文字，拍照草稿的修改附带对应原图。AI 返回格式错误或请求失败时保留原草稿，手动编辑也会进入后续 AI 的最新上下文。
- 取消翻页、揭晓答案时的整页淡入；倒计时只原位更新数字，不重新创建页面。
- 今日巩固完成后，首页和完成页均可开始下一轮，默认另外 30 个，跟随每日数量设置；不足一轮时按实际数量显示。
- 下一轮优先延续跨日未完成内容，再选择到期内容；不足时提前复习尚未在今天练过的普通内容。重点和未到期的标熟内容保留原计划，不通过修改系统日期模拟次日。
- 下一轮独立保存轮次、答题和撤销进度，支持强退后继续。当天无剩余内容时不再提供下一轮按钮。
- 名称和图标更新为 Carmanline。
- 首页改为简洁布局：品牌、公式/错题切换、今日巩固、重点复习及底部导航。
- 使用暖纸色背景、陶橙色主色与深棕文字。
- 公式和错题列表均支持多选、全选当前列表、取消选择和删除确认。
- 删除内容时同步清理复习会话、延后队列和撤销快照，避免重启或撤销后恢复已删除内容。

## 使用

首页底部“录入”可拍照或从相册选图。真实识别需要配置支持图片输入的兼容 Chat Completions 服务。接口地址需完整到 `/chat/completions`，API Key 由用户填写。原有设置不会被升级覆盖。

使用外部 AI：选择“公式”或“错题”板块 → JSON 导入 → 复制对应提示词 → 和照片一起交给其他 AI → 粘贴返回结果或选择文件 → 校验并预览 → 逐条或全部确认入库。严格格式说明及独立提示词见 `docs/import-format.md` 和 `docs/prompts/`。

对话修改每次作用于当前一条待录入草稿，支持多轮追问和手动改动；不会直接修改已入库内容。照片和对话记录仅保留于当前页面内存，完成入库或清除时释放；未确认草稿在关闭进程后需重新录入。

复习、公式渲染与字体均可离线使用。每条内容连续答对两次完成当日巩固；跨日使用六盒排程。重点清单每日单独复习。Android 端使用同步原生保存，支持立即强退后继续。

## 开发与构建

```powershell
npm.cmd install
python scripts/bootstrap_android.py
npm.cmd test
npm.cmd run build:android
```

运行环境：Android 7.0 / API 24 起；实际验证使用 Android 11 系统自带 WebView 83。构建使用 Android 官方 aapt2、d8、zipalign、apksigner；JDK、SDK 和当前签名密钥放在忽略版本管理的 `.tools/` 中。请保留本机 `.tools/demo-signing.jks`，后续原地更新仍需相同签名。

界面由本地 WebView 承载，KaTeX 及字体打包离线使用。`web/state.mjs` 处理数据升级和删除，`web/core.mjs` 处理复习状态机。默认题目只保留为 `tests/fixtures.mjs` 中的测试数据，不进入 APK。

网页预览：先运行 `node scripts/prepare-assets.mjs`，再运行 `npm.cmd start`。手机界面测试：`node scripts/verify-ui.mjs`；倒计时及连续三轮测试：`node scripts/verify-review.mjs`；录入流程：`node scripts/verify-import.mjs`；清除、部分成功及中断恢复：`node scripts/verify-input-v031.mjs`。这些测试使用确定的 AI 返回测试替身，不向外部模型发送数据。设置 `DEMO_URL` 可直接使用本地 `web/index.html` 的 file URL，避免本地网络权限依赖。安卓升级、文件选择及新录入操作使用 `scripts/verify-android-v031.mjs`，仅限本项目的 FormulaDemo 模拟器。

`dist/ui-verification.json`、`dist/review-verification.json`、`dist/import-verification.json`、`dist/input-verification.json` 与 `dist/android-verification.json` 保存本版验证记录。安卓记录包含所验证 APK 的 SHA-256；AI 生成结果以测试替身验证，真实服务是否返回有效结果取决于用户配置的模型。

## 工具与凭据

此前安装的官方 Synergy 3.1.3 及其 Windows 兼容启动脚本保留在当前工作区。可通过 `python scripts/run-synergy.py --version` 使用。其运行目录和授权配置位于 `.synergy-local/`，不进入版本管理或交付包。

API Key 使用 Android Keystore 的 AES-GCM 密钥加密保存在手机本机。交付打包会检查 APK 与源码一致，并扫描开发凭据；源码包不含本机模型配置或签名密钥。
