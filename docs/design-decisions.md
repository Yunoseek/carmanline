# Demo 实现决定

参考来源：用户提供的设计手册 v2.0 与四张界面截图。截图用于视觉和答题反馈参考；调度来自手册。

## 日内与跨日

日内记录连续答对数、连续失败数和本轮发生过的遗忘。日内答对两次不代表升两盒；当某个内容完成本场时，用本场开始的盒位和本场结果结算一次：

| 本场情况 | 跨日结算 |
| --- | --- |
| 发生过“不会”或看答案 | 第 0 盒，次日再见 |
| 发生过“我是蒙的” | 原盒位降一级，最早次日 |
| 全程记起 | 原盒位升一级，上限第 5 盒 |
| 首次纠正为手滑，随后完成 | 保持原盒位 |

当队列足够长时，答对后隔至少五题，答错后隔至少三题。当只剩少量内容时，显示 20 / 30 秒短暂停顿，不以“下一题”立即重复同一内容。该时间是 Demo 的体验设置。

## 重点清单

连续失败五次转入重点，成功一次会清除连续失败计数。进入当天不立即额外刷一次；之后每天最多出现一次。连续三次出题成功后毕业，跳过的自然日不清空进度。

## 标熟

手册“标熟不进队列”与“30 天后重新检验”存在歧义。本实现采用：30 天到期前不进普通队列，到期后重新检验；失败后解除标熟。

标熟保存原调度状态，顶部撤销恢复该状态。跨日算法按实际提交的本地日期安排下一次复习。

从题库取消标熟时，也恢复该内容在当前会话中的进度，只移除对应标熟事件，并重设后续快照中该内容的状态；其他题目的撤销记录继续保留。

## 强退保存

Android 端每次提交进度使用原生同步落盘，避免 WebView localStorage 的异步写入在立即强退时丢失最近一条判定。浏览器预览使用 localStorage。

## 跨日打开

正在答题时跨过零点不会打断当前页面。次日重新从首页进入时，先把未完成内容及其连续通过数放入新一天名额，再补齐到期内容；尚未提交的揭晓页原样保留。降低每日数量后放不下的未完成内容单独保留，继续顺延。

## 录入与数据

照片保留在当前录入批次的内存中。API 返回的正确公式必须人工核对；KaTeX 校验只保证可渲染，不保证数学正确。无法渲染或混淆项不足的结果会跳过并提示。

相机临时文件使用限于本应用缓存目录的 ContentProvider；不申请整个相册的读取权限。模型地址与密钥由用户配置；导出数据包括题库、调度状态和当前会话。


## 0.2.0 空题库与编辑

新安装不创建示例内容。升级迁移仅清理旧版固定示例 ID，保留用户的 custom-* 录入记录、接口设置及仍有效的复习进度。

“全选”作用于当前题型和当前科目筛选结果。切换筛选会清除当前选择，避免不知情地删除隐藏条目。删除前有二次确认；取消不改变数据。删除后同时移除会话的当前题、队列、延后内容和历史快照引用，防止撤销或跨日续接将其带回。

首页参考不背单词的主体品牌、底部双卡片和三入口导航，使用暖纸色与陶橙色，不添加额外统计图或文案区块。

## 0.2.1 稳定页面与后续轮次

取消所有 page-enter 的淡入与位移动画，避免每次整页重绘时透明度从低值重新开始。等待页面保留同一 DOM，只更新数字文本，数字宽度固定；计时结束只切换一次到题目页，离开等待页会取消计时任务。

完成每日组后可主动开始下一轮，默认最多 30 条，使用当下数量设置。优先未完成的延后队列和到期内容，其次按最近到期日提前复习；当日已练过、重点内容和未到期的标熟内容不加入。各题依然以真实提交日期计算盒子与下次到期日，不更改系统日期，不虚增连续复习天数。

新一轮保留独立轮次号和答题历史。不能在未完成时另开一轮；当日再次打开继续当前轮次，次日重新按轮次 1 接续未完成内容。首页与完成页共用同一候选规则；不足数量显示实际数量，耗尽后不提供继续按钮。

## 0.3.0 两条录入路径

照片识别和外部 JSON 共用内容草稿与逐条核对流程。外部 JSON 按公式和单选错题分别定义版本化格式；禁止 ID、设置和排程字段，整批验证通过才进入预览。导入只追加新内容，精确重复会跳过；保存失败回滚新增内容并保留当前核对位置。

修改页采用聊天窗口，当前草稿可展开，消息单独滚动，输入框保持可见。多轮请求只附带当前条目、最近有效对话及对应原图，不发送整个题库。纯 JSON 草稿不附图。AI 结果先通过与手动编辑相同的字段及 KaTeX 检查，验证失败或网络错误保留原草稿。批次令牌阻止旧请求覆盖新批次，处理中不能确认入库或跳到下一条。

Android 的同一 HTTPS 服务支持纯文字 messages 和可选图片；复制使用系统剪贴板，JSON 文件使用系统文档选择器，照片选择继续支持相机。所有数据导入和确认操作均可离线执行，只有识别与对话请求依赖模型服务。草稿和照片不写入长期复习数据。

## 0.3.1 清除输入与部分成功

JSON、图片读取和识别分别使用递增令牌。清除输入会重置该来源的错误和未入库草稿，迟到的文件读取、照片解码和网络结果无法恢复它们；已经保存的题库不受影响。编辑 JSON 时也使未完成的文件读取失效，避免旧文件覆盖新文字。清除只让迟到结果失效，不承诺取消已经发出的服务端生成请求。

每项独立校验并记录失败原因，有效项继续进入入库预览；一张照片失败后继续下一张。无效混淆项可过滤，但不能为不足三项的公式凭空生成替代内容。外部 JSON 的结构和语法依然严格校验，不自动改写反斜杠。

原图和 bbox 不再用于核对展示或裁剪；文本与公式预览保留编辑能力，照片和 JSON 都可整批入库。原图只在当前录入批次的 AI 修改请求中按需附带。

拍照返回携带原始模型内容和 finish_reason。只有服务明确报告 length、aborted 或 insufficient_system_resource 时，才扫描顶层 items 数组并恢复完整对象；残缺对象不猜补。结果始终提示中断和可能遗漏。空回复、外层响应错误和 AI 修改的格式错误使用简短提示，避免 Android JSON 异常将整段输入暴露到错误界面。
